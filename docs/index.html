// FOUNDATIONS 01

What is cryptography?

Cryptography is the science of keeping information safe when other people might be watching it, or trying to change it.

ConfidentialityCan anyone else read it?TOOLS FOR THISEncryption (AES, RSA)
IntegrityWas it changed on the way?TOOLS FOR THISHashing (SHA-256) and tamper checks (GCM)
AuthenticationWho am I really talking to?TOOLS FOR THISPasswords, certificates, signatures
Non-repudiationCan the sender deny sending it?TOOLS FOR THISDigital signatures

You use all four every day: messaging, online banking, logging in, and every https:// page.

~3 min. Ask: which of these four goals does a banking app need? (All four.) Define each in plain words. Confidentiality = secrecy; integrity = unchanged; authentication = who; non-repudiation = can't deny.

// FOUNDATIONS 02

Your first cipher: the Caesar shift

Plain alphabet / cipher alphabet: every letter shifted forward by the key

Try itTo encrypt, replace each letter with the one 3 places later: H becomes K, E becomes H. To decrypt, shift back by 3. The key is just the number 3.
Why it is weakThere are only 25 possible keys, so a computer tries them all in an instant. Letter counts also give it away: the most common letter is probably E.
What modern ciphers fixA huge number of keys, so guessing is hopeless. Heavy scrambling that hides letter patterns. And the method can be public: only the key is secret.
~3 min. Live demo idea: have students decrypt KHOOR by hand. Then ask how they would crack a long Caesar message (try all 25 shifts; count letters). Lesson: small key space and visible patterns are fatal. Next slide cracks it live.

    // FOUNDATIONS 03
    The Vigenère cipher: a keyword, not one shift
    
  
    
    
    
      
      
    
    
    
    
    
    
    
    
      
    Why it was a big stepCounting letters no longer works, because E is not always the same letter. People called it "the unbreakable cipher" for about 300 years.
    
      
    Why it still failsThe keyword repeats. Codebreakers found the key length from repeated patterns, then solved each position like a Caesar cipher (1800s).
    
    
    
  
    
  
    ~4 min. Work the first two letters aloud: A with L shifts 11, T with E shifts 4. Point out the four A's turning into four different letters, which defeats letter counting. Then explain the weakness: the key repeats, so patterns leak the key length.

    Show the spike at the true key length, then the recovered keyword. Ask: what if the key never repeated? (Next slide.) Try a keyword longer than 12 letters on the previous slide to see the attack fail.
    

    



    
  
    // FOUNDATIONS 04
    The one-time pad: a key that never repeats
    
  
    
    
    
      
    
        
        
      
    
      
    
      
    
      
    
    
    
    
    
      
    The four rules
    
      
      
        
    • Truly random, not a pattern or a phrase
      • 
        
    • At least as long as the message
      • 
        
    • Used once, then thrown away
      • 
        
    • Kept secret, and shared safely beforehand
      • 
      
    
      
    Break rule 3 and it falls apart

This returns later as XOR and as nonce reuse in AES modes.

    The Enigma machine: a cipher built from gears
    
  
    
    
    
      
    Press a key: plugboard → 3 rotors → reflector → 3 rotors → plugboard → a lamp lights. The rotors turn after every key press. Click the keys, or click the keyboard and type.
    
      
    
        
        
      
    
      
      
    
      
    
    
    
    
    
      
    AAA

    // FOUNDATIONS 05 · HOW IT FELL
    Enigma: clever, but it still fell
    
  
    
    
    
      
    Press A five times
    
      
    
      
    Why it was cleverRotor order, start positions and plugboard cables gave about 159 quintillion possible settings. To decrypt, you type the secret message into a machine with the same settings.
    
    
    
    
    
      
    
      
    Why it still fellA letter never became itself, and operators repeated predictable phrases. Polish mathematicians, then Alan Turing's team at Bletchley Park, built machines to test settings quickly.
    
    
    
  
    
  
    Ask: what does it mean that a letter can never become itself? (It leaks information, and codebreakers used it.) Link back to the one-time pad: Enigma was a very complicated Vigenère-style cipher with a repeating-but-huge key. Settings are the key, and they had to be shared in advance: the key-distribution problem again.

      // HASHING 01
      How hashing works
      
  
      
    
      
      
      
        
      Deterministic and fastSame input always gives the same hash. Quick to compute.
      
        
      Fixed-size outputA single letter or a whole movie both give 256 bits.
      
        
      Avalanche effectChange one input bit and about half the output bits change.
      
        
      One-wayGiven a hash, the only way to find the input is to guess.
      
        
      No twinsIt should be practically impossible to find two inputs with the same hash.
      
      
      
      
      How MD5, SHA-1 and SHA-2 process a message: pad it, cut it into blocks, mix each block into a running result
        
      IVf ← M1f ← M2f ← M3hash
      
    
      
    
      
      
      Avalanche, live
      
      
      
        
        
      
      
      
      
      
      
      
      
    
      
  
      
  
      ~4 min. Four properties: deterministic, fixed size, avalanche, one-way. Show the block diagram: pad, split, mix each block into a running value. Flipping bit 2 of "hello" gives "Hello", the title-slide example.

      // HASHING 03
      Known issues: MD5 and SHA-1 are broken
      
  
      
    
        
      
      1. 1995SHA-1 becomes a US standard
        2. 
      
      2. 2004Researchers find two inputs with the same MD5 hash
        3. 
      
      3. 2008Fake website certificate made using the MD5 weakness
        4. 
      
      4. 2012Flame malware fakes a trusted software signature (MD5)
        5. 
      
      5. 2017SHAttered: first SHA-1 collision, found by Google
        6. 
      
      6. 2020Faster SHA-1 attack: "SHA-1 is a Shambles"
        7. 
    
      
    
      
      
      MD5 (128-bit)Two different inputs can be made to match in seconds. Cannot be trusted for signatures or certificates. A graphics card tries billions per second, so it is useless for passwords.
      
      
      SHA-1 (160-bit)Attacks have made it much cheaper to break. Two different PDFs with the same SHA-1 hash were published in 2017. Browsers and certificate authorities have dropped it.
      
      
      Use insteadSHA-256, SHA-384 or SHA-512 (the SHA-2 family). SHA-3 (a newer, different design). BLAKE2 / BLAKE3 for speed. For passwords: Argon2id, bcrypt, scrypt.
      
    
      
  
      
  
      ~3 min. Timeline of breaks. Key message: "broken" means attackers can make collisions on purpose. Use SHA-256 or SHA-3 for new work.

      Find a collision yourself

      // HASHING 04
      Salt and pepper
      
  
      
    
      
      
      
    
      
    
      
      
      No salt
      
      
      Salt random, unique, stored beside the hash
      
      
      Pepper secret, shared, kept outside the database
      
    
      
    
      Salt defeats rainbow tables (huge lists of pre-computed hashes) and is not secret. Pepper lives in a vault, is hard to change later (track which version was used), and is mixed in before hashing.
      
  
      
  
      ~4 min. Ask: why store the salt next to the hash? (It isn't secret; it just forces attackers to work per user.) Pepper is secret and kept outside the database.

        Symmetric vs asymmetric encryption
        
  
        
    
        
      
        SYMMETRIC · one shared key
        Alice KciphertextBob K

        // ENCRYPTION 03
        AES: the standard symmetric cipher
        
  
        
    
        Plaintext 128 bitsAddRoundKeySubBytesShiftRowsMixColumnsAddRoundKeyCiphertext 128 bits
        
    
        Repeat the middle four steps each round (the last round skips MixColumns)
        
    
        
      
        
        
        SubBytesEach byte is swapped using a fixed lookup table (the S-box). This hides patterns: confusion.

        AddRoundKeyThe block is combined (XOR) with the round key. This is the only step that uses the key.
        
      
        
      
        
        
        
          b0b4b8b12b1b5b9b13
          b2b6b10b14b3b7b11b15
        
        
        
        16 bytes, filled column by column
        
        
        10rounds · AES-128
        12rounds · AES-192
        14rounds · AES-256

        // ENCRYPTION 06
        Known issues with certain AES modes
        
  
        
    
        ECB: patterns survive
        Identical blocks of the original data become identical blocks of encrypted data, so the shape of an image still shows through.
        Fix: never use ECB.
        
    
        CBC: padding leaks
        If a server reveals whether the padding (filler bytes) was valid, an attacker can decrypt the message bit by bit (POODLE, Lucky13). Predictable IVs allowed the BEAST attack.
        Fix: use authenticated encryption (like GCM), or add a tamper check.
        
    
        CTR: nonce reuse
        Reusing a nonce (a number meant to be used once) repeats the scrambled stream, so attackers can combine two messages and cancel it out. Tampering also goes unnoticed.
        Fix: never repeat a nonce; add a tamper check.
        
    
        GCM: never reuse a nonce
        Repeating a nonce leaks the secret behind the tamper check, so attackers can forge messages. Random nonces can collide after about 4 billion messages.
        Fix: use counters for nonces, change keys often, or use AES-GCM-SIV.
        
  
        
  
        ~4 min. Four flaws: ECB patterns, CBC padding oracle, CTR nonce reuse, GCM nonce reuse. The next three slides show ECB and nonce reuse live.

        Plain CTR (no tag)

        // ENCRYPTION 08 · NONCES
        Never reuse a nonce
        
  
        
    
        
      
        How GCM works
        
        nonce + counterAES encryptmix with messageciphertext C

          RSA with small real numbers
          
  
          
    
          
      
          
        
        
        
        
      
          
      
            
      
            
    
            
    
            
      
            Why it works
            
      
              
        
            • Locking raises the message to the power e (and keeps the remainder after dividing by n)
              •

              •

            // ASYMMETRIC 03
            RSA in practice: the secure modes
            
  
            
    
            
      
            Textbook RSA is unsafe
            
      
            
      
            
        
        
      
            
      
            
      
            Old padding (PKCS#1 v1.5) was broken by attacks in 1998 and again in 2017 (ROBOT).
            
    
            
    
            
      
            Safer RSA
            
      
              
        
            • OAEP for encryption: adds randomness before encrypting
              • 
        
            • PSS for signatures: padding with a random salt
              • 
        
            • Use keys of 2048+ bits (3072 for long-term data)
              • 
        
            • Use RSA to sign or to protect a symmetric key, not to encrypt lots of data
              • 
      
            
      
            RSA-OAEP: add randomness first
            message m + paddingscramble with random seedRSA lock (x^e mod n)ciphertext
            Encrypting the same message twice now gives different ciphertexts.
            
    
            
  
            
  
            ~3 min. Textbook RSA is unsafe: predictable, malleable, and short messages are easy to undo (run the e = 3 attack). Generating a 2048-bit key takes a second or two in plain JavaScript. Real systems use OAEP (encrypt) and PSS (sign), with 2048+ bit keys.

              // WRAP-UP
              Key takeaways
              
  
              
    
              Hash is not encryptA hash is a one-way fingerprint. Encryption is reversible with the key.
              
    
              Store passwords properlyDrop MD5 and SHA-1. Use Argon2id or bcrypt with a unique salt, plus a pepper.
              
    
              Use AES-256-GCMIt detects tampering. Never use ECB, and never reuse a nonce.
              
    
              Asymmetric for keysUse RSA (2048+ bits, with padding) or ECC to share keys and sign.
              
    
              Built on hard puzzlesRSA, ECC and post-quantum schemes each rest on a puzzle that is easy one way and hopeless to reverse.
              
    
              Plan for quantumList where you use crypto, be ready to swap it, try hybrid ML-KEM, and prefer AES-256.
